# Claude ranking output validation

A source with 30 saved candidates failed ranking twice. The local usage ledger showed four responses at exactly 2,200 output tokens, the old request limit. This strongly indicates truncation. The adapter discarded `stop_reason` and stored only usage, so the precise stop reason and any additional formatting or ID errors in those historical responses cannot be recovered. A successful HTTP response in the ledger records billable usage. It does not establish that Montaj accepted the grades.

Claude Sonnet 5.5 enables adaptive thinking by default and counts thinking and answer text against the same output cap. Montaj now requests 4,096 output tokens for rank and uses Sonnet 5.5's `between_tools` setting to reserve that space for the result in this tool-free request. The other Claude stages keep their existing request settings. The rank rubric and one-request comparison stay intact so the highest scores are selected globally, with clip ID breaking ties. [Claude Sonnet 5.5](https://platform.claude.com/docs/en/models/sonnet-5-5/overview) · [Claude stop reasons](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons)

The adapter settles actual usage before checking whether Claude reached `end_turn`. Truncation, refusal, invalid JSON or field values, and duplicate, missing, or unexpected IDs produce sanitized diagnostics. A rejected response creates no ranking or grade cache. Montaj does not automatically resend it. Transport retries still use the existing retry policy and budget reservations. Valid cached grades remain reusable for another `--top` selection, and existing reviewed and approved clip records are protected.

For future failures, compare the terminal diagnostic with the rank entries in the usage ledger. Inspect token counts, estimated cost, and outcome without copying prompts, excerpts, provider bodies, or grade text. If the response reached the output cap, adjust the request configuration or reduce the eligible set before another paid attempt. If a saved cache fails validation, move only the named cache aside before retrying. The maximum output reservation rises by $0.018960 at the configured Sonnet 5.5 estimate. Actual charges follow the provider's reported usage.

Offline tests cover 30 grades, global top three, malformed outputs without a second request, stop-reason handling, budget refusal, recovery, cache reuse, and approved record preservation. The live 30-candidate retry remains an operator action. For a Compose deployment, rebuild the image first so the retry runs the updated code. Then run `docker compose run --rm montaj rank 1 --top 3` with the existing budget ceilings.
